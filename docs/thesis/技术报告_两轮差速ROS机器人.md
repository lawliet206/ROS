# 两轮差速ROS机器人技术报告

## 一、方案选型与理由

### 1.1 系统架构

采用"PC—车载工控机—下位机"三机分布式架构，各司其职：

- **PC端**：作为ROS主节点，运行SLAM建图、AMCL定位、move_base路径规划、YOLO视觉检测等计算密集型任务。PC拥有最强算力（Intel处理器，8GB以上内存），适合运行这些需要大量计算资源的算法

- **J1900工控机**：车载x86工控机，通过WiFi与PC通信。主要负责激光雷达驱动（解析串口数据并发布扫描消息）、串口桥接（通过rosserial协议与ESP32通信）、摄像头推流（压缩图像传输给PC端YOLO检测）。工控机算力适中（Intel赛扬J1900，4核4线程），足以处理这些中等负载任务

- **ESP32下位机**：通过USB串口与J1900连接，运行rosserial协议。负责底层实时控制：电机PID控制（100Hz）、编码器计数（PCNT硬件计数器）、IMU数据采集（MPU6050）、里程计计算。ESP32双核240MHz主频，实时性好，适合控制任务

**选择理由**：单机方案（如树莓派）算力不足，难以同时运行SLAM和视觉检测，且GPIO资源有限；纯嵌入式方案无法运行ROS生态的成熟算法。三机架构将计算密集任务放PC端，实时控制放ESP32端，中间由工控机承担驱动和通信，实现算力与实时性的平衡，同时保持系统灵活性和可扩展性。

### 1.2 底盘选型

两轮差速+万向轮支撑方案，是室内移动机器人最经典的底盘结构。

**运动原理**：左右两个独立驱动轮，通过转速差实现前进、后退、转向和原地旋转。车体前方和后方各有一个万向轮作为支撑，不提供驱动力，只起平衡作用。这种结构简单可靠，成本低，运动学模型成熟，控制算法简单。

**参数设计**：
- 轮距（左右轮中心距）：180mm。轮距影响转弯半径和稳定性，过小则转弯半径小但稳定性差，过大则稳定性好但转弯不灵活。180mm是平衡点
- 轮径：85mm。配合电机减速比1:10，最大线速度可达4.45米每秒，远超室内导航所需的0.6米每秒
- 底盘尺寸：约300×250mm，紧凑灵活，适合室内环境

**对比其他方案**：
- 阿克曼转向底盘：结构复杂，需要转向机构，成本高，不适合低成本项目
- 全向底盘（麦克纳姆轮）：可实现全向移动，但轮子成本高，控制算法复杂，对地面平整度要求高
- 履带底盘：适合复杂地形，但在室内硬质地面上效率低，转弯磨损大

### 1.3 传感器选型

- **激光雷达**：S9低成本雷达，价格仅商业雷达1/4，通过逆向解析实现360度扫描。扫描频率约5赫兹，单帧约39个测量点，满足室内建图和导航需求
- **IMU**：MPU6050六轴模块（三轴加速度+三轴陀螺仪），成本约10元，通过I2C接口与ESP32通信，用于姿态解算和里程计融合
- **编码器**：电机内置霍尔编码器，AB双相输出，11脉冲/转，四倍频后每转44个计数，满足速度和位移测量精度
- **摄像头**：USB免驱摄像头，分辨率640×480，帧率30fps，配合YOLO算法实时检测人体目标

### 1.4 导航算法

- **SLAM建图**：gmapping算法，基于粒子滤波，通过激光扫描匹配构建栅格地图。在计算资源受限的嵌入式平台上依然实用，参数调优经验成熟
- **定位**：AMCL（自适应蒙特卡洛定位），在已知地图上用粒子滤波实现全局定位，通过激光匹配修正里程计累积误差
- **路径规划**：全局规划使用Dijkstra算法搜索最短路径，局部规划使用TEB（时间弹性带）算法，显式考虑机器人的运动学约束，输出平滑的轨迹
- **传感器融合**：使用扩展卡尔曼滤波（EKF）融合编码器里程计和IMU数据，降低单一传感器的噪声和漂移

## 三、软件架构

### 3.1 系统架构

```
PC (ROS Master)
  ├── gmapping (SLAM建图)
  ├── AMCL (定位)
  ├── move_base + TEB (导航)
  ├── robot_state_publisher (TF发布)
  ├── EKF融合 (里程计+IMU)
  └── YOLOv8n (人体检测)
       │ WiFi (约5ms延迟)
       ▼
J1900 (车载工控机)
  ├── s9_lidar_driver (雷达驱动，发布/scan)
  ├── serial_node (rosserial桥接)
  ├── usb_cam (摄像头推流)
  └── compressed_image_transport (压缩)
       │ USB串口 (115200波特率)
       ▼
ESP32 (下位机)
  ├── PCNT硬件编码器 (左右轮)
  ├── 双路PID控制 (100Hz)
  ├── MPU6050 IMU (I2C)
  ├── 里程计计算
  └── rosserial (发布/odom,/imu，订阅/cmd_vel)
```

**通信协议**：
- PC与J1900：WiFi局域网，ROS主从模式。PC作为主节点，J1900作为从节点，话题自动发现和同步
- J1900与ESP32：USB串口，rosserial协议。自动协商话题列表，序列化ROS消息传输
- J1900与雷达：USB串口，自定义AA55协议，115200波特率
- J1900与摄像头：USB，compressed_image_transport压缩传输，减少带宽占用

**话题列表**：
- /odom：里程计（ESP32发布，8Hz）
- /imu：惯性测量单元数据（ESP32发布，4Hz）
- /scan：激光扫描（J1900发布，5Hz）
- /cmd_vel：速度指令（PC发布）
- /camera/image/compressed：压缩图像（J1900发布，15fps）
- /person_visible：人体检测结果（PC发布）
- /person_angle：人体偏角（PC发布）

### 3.2 ESP32固件

ESP32下位机固件是整个系统的底层核心，负责电机控制、传感器数据采集和安全保护。

**主要功能模块**：

- **PCNT硬件编码器**：使用ESP32的脉冲计数器外设，硬件自动计数，四倍频后每转44个tick。相比软件中断方式，不会因CPU忙而漏脉冲，高速时计数准确
- **双路PID控制**：左右电机独立PID控制，控制频率100赫兹。采用位置式PID，微分项作用于测量值而非误差，避免设定值突变时产生过冲。输出限幅保护电机
- **里程计计算**：根据编码器计数、轮半径、轮距、减速比，实时推算机器人在全局坐标系下的位置和朝向。通过rosserial协议以8赫兹发布里程计消息
- **IMU解算**：读取MPU6050原始数据，通过互补滤波融合加速度计和陀螺仪，解算姿态角。以4赫兹发布角速度和线加速度
- **安全机制**：800ms看门狗超时自动停车（防止通信中断后失控），堵转检测（命令转速大于80但实际小于1持续2秒则切断PWM），电池电压监测

**关键机械参数**：
- 轮径：85mm（橡胶轮实测）
- 轮距：180mm（左右轮着地点中心距）
- 减速比：1:10（JGB37-520电机）
- 编码器：11脉冲/转（霍尔传感器）
- PWM分辨率：10位（0-1023）
- 控制频率：100赫兹

### 3.3 S9雷达驱动

S9激光雷达协议不公开，通过串口抓包和数据分析逆向解析出帧格式，实现了完整的驱动程序。

**帧格式解析**：
- 帧头标识：AA 55（2字节）
- 控制字：1字节
- 测量点数：1字节（每帧约39个点）
- 起始角度：2字节（单位1/64度）
- 结束角度：2字节
- 校验和：2字节
- 测量数据：每点3字节（质量1字节+距离2字节，小端序）

**关键算法**：
- 定长解析：根据点数字段确定帧长度，避免载荷内偶然出现的帧头干扰
- 跨零检测：起始角度从大于260度跳回小于100度时，判定一圈扫描完成，触发发布
- 角度映射：原始数据为顺时针递增，需镜像变换为逆时针，再加偏移补偿使车头方向对应0度
- 距离换算：实测标定原始值除以4000得到米，例如0.7米墙壁对应原始值约2760

**测试验证**：编写15项回归测试，覆盖帧解析、角度映射、距离换算、异常处理等场景，确保驱动正确性。

### 3.4 视觉跟随

提出"视觉定方向、激光定距离"的融合跟随策略，弥补单一传感器的不足。

**视觉通道**：
- 使用YOLOv8n轻量级目标检测模型，参数量仅3.2M，适合嵌入式CPU实时运行
- 检测人体目标（COCO数据集类别0），输出边界框中心的水平偏角
- 帧率约15fps，满足实时控制需求

**激光通道**：
- 对激光扫描数据进行聚类，基于欧氏距离将相邻点分组
- 筛选符合人体宽度特征的簇（0.2-0.5米），排除墙壁、柱子等干扰
- 计算最近簇的中心距离和角度

**融合状态机**：
- 跟随态：视觉和激光均有效，综合两路数据输出速度指令
- 搜索态：视觉丢失但激光有效，机器人左右摇摆（正负60度）搜索目标
- 停止态：两者均丢失，停车等待目标重新出现

**控制策略**：
- 角速度：根据目标偏角比例控制，快速对准目标
- 线速度：只有对准后（偏角小于17度）才前后移动，根据距离误差调整
- 目标锁定：连续3帧检测到目标后进入锁定状态，使用指数移动平均平滑数据

### 3.5 导航流程

一键启动脚本自动完成：
1. 启动roscore（PC端ROS主节点）
2. 通过SSH远程启动J1900的雷达驱动和串口桥接
3. 等待真实话题数据（里程计、IMU、激光扫描）
4. 启动gmapping建图或AMCL定位+move_base导航
5. 打开键盘控制窗口或自动巡航脚本

导航参数配置：
- 全局规划器：navfn（全局路径搜索）
- 局部规划器：TEB（时间弹性带，考虑运动学约束）
- 最大线速度：0.6m/s
- 最大角速度：1.0rad/s
- 加速度限制：0.5m/s²
- 障碍物膨胀半径：0.3m

巡航模式支持多点循环，通过配置文件设定目标点坐标，机器人自动规划路径并依次到达。

| 跟随稳定性 | 1.2m/s散步速度 | 稳定保持1.0米距离 |
| 丢失恢复 | 目标走出视野 | 正负60度摇摆搜索后自动恢复，约3秒 |
| 响应延迟 | 观察运动响应 | 小于0.5秒 |
| 距离精度 | 激光实测 | 误差正负15厘米 |
| 宽度筛选 | 不同宽度物体 | 正确筛选人体宽度（0.2-0.5米） |

**融合效果**：纯激光跟随时，角度分辨率不足导致对准慢；纯视觉跟随时，缺少深度信息无法控制距离。融合方案结合两者优势，对准快、距离稳。

## 五、问题与解决方案

### 5.1 已解决的问题

| 问题 | 原因分析 | 解决方案 |
|------|----------|----------|
| 编码器漏脉冲 | 原来用软件中断计数，CPU忙时响应不及时 | 升级为PCNT硬件编码器，硬件自动计数不漏脉冲 |
| 轮距参数不一致 | URDF模型、launch文件、ESP32固件、仿真环境各自定义 | 统一为0.180米，由单一配置文件管理 |
| 雷达协议不公开 | S9是低成本雷达，厂家不提供文档 | 通过串口抓包逆向解析帧格式，实现驱动 |
| 导航路径绕远路 | 使用navfn全局规划器，容易陷入局部最优 | 切换为TEB局部规划器，考虑运动学约束 |
| 轮子起步打滑 | 橡胶轮静摩擦力大，低PWM无法克服 | 增加启动死区补偿（450 PWM），提高起步扭矩 |
| 里程计漂移 | 纯编码器积分累积误差 | 引入EKF融合IMU数据，修正漂移 |
| 仿真鬼影障碍物 | gmapping参数minimumScore太低 | 调高到300，过滤低置信度匹配 |

### 5.2 当前存在的问题

| 问题 | 现象描述 | 可能原因 | 后续改进方向 |
|------|----------|----------|--------------|
| 导航路径偶有绕远路 | 全局规划路径不够优化 | costmap膨胀参数设置 | 调整inflation_radius，优化障碍物膨胀 |
| 到达目标前速度震荡 | 接近目标时速度不稳定 | TEB优化收敛慢 | 增加tolerance参数，放宽到达精度 |
| 仿真地图轻微鬼影 | 地图有虚假障碍物残留 | gmapping参数还需微调 | 继续调优minimumScore和粒子数 |
| 左右轮速度差异 | 直行时有轻微偏航 | 电机个体差异 | 独立调整左右轮PID参数 |

### 5.3 调试经验总结

1. **先仿真后实物**：在Gazebo仿真中验证算法逻辑，再部署到实物，避免损坏硬件
2. **参数单一来源**：轮距等关键参数只在一处定义，其他地方引用，避免不一致
3. **日志充分记录**：关键节点添加日志输出，便于排查问题
4. **逐步集成验证**：先验证单个模块（电机、雷达、IMU），再逐步集成，每步验证通过再继续
5. **安全机制优先**：看门狗、堵转检测、电压监测等安全功能必须在早期实现

## 六、结论

本项目完成了一套基于ROS的低成本两轮差速移动机器人系统，实现了从硬件搭建、底层驱动到上层算法的完整工作。

**主要成果**：

1. **三机分布式架构**：PC运行SLAM和导航算法，工控机承担雷达驱动和通信中继，ESP32实现实时控制。合理分配算力，兼顾性能与实时性，架构清晰可扩展

2. **低成本传感器方案**：通过逆向解析S9雷达协议，以商业雷达四分之一的成本实现360度激光扫描。结合MPU6050 IMU和电机编码器，用低成本传感器组合满足导航需求

3. **视觉-激光融合跟随**：提出"视觉定方向、激光定距离"策略，视觉通道用YOLO检测人体偏角，激光通道聚类提取距离，通过状态机融合输出控制指令。在1.2米每秒散步速度下稳定跟随，丢失后自动搜索恢复

4. **一键部署方案**：设计一键启动脚本，自动完成建图、导航、跟随等功能的部署，通过SSH远程管理车载设备，降低使用门槛

5. **完整测试体系**：建立单元测试、仿真验证、实物联调三级测试，15项雷达回归测试确保解析正确性，全部功能通过实测验证

**技术指标达成情况**：

| 指标 | 目标 | 实际 |
|------|------|------|
| 最大线速度 | 大于1.0m/s | 4.45m/s |
| 定位精度 | 小于10厘米 | 约5厘米 |
| 建图成功率 | 大于90% | 100% |
| 跟随距离 | 1.0米正负20% | 1.0米正负15% |
| 跟随速度 | 大于1.0m/s | 1.2m/s |
| 丢失恢复时间 | 小于5秒 | 约3秒 |

**后续改进方向**：
- 引入深度相机获取三维点云，提升避障能力
- 集成ROS2，利用其安全机制和实时性改进
- 增加语音交互模块，实现更自然的人机交互
- 优化导航参数，减少路径绕远和速度震荡问题
